# dsh-chronicle 审计与修订反哺报告（2026-11-13 / v2.3.1）

> 对象：`dsh-chronicle` v2.3.1（起居注）· 本机已装发布包 + GitHub 源 `zuoyunlai/dsh-chronicle@4393300`
> 方法：机械体检（`plugin_doctor`）→ 活体探测（10 个工具 + 面板 API 实跑）→ 主审通读 → 三路独立复核（数据管线 / 宿主契约 / 性能资源）
> 口径：本报告每条都带**代码位置或实测数据**；核实不成立的会写明「推翻」及理由，不做美化。

## 1. 总评：6.0 / 10

**从上一轮 4.5 提到 6.0：护栏明显变厚、注释密度罕见地高，但「自动收口」这条核心承诺在生产里一次都没真正跑过，而两条完成判据各写一半。**

| 维度 | 分 | 主要扣分 |
|---|---|---|
| 数据正确性 | 5 | 11-12 丢 60.6% 事件；21 条 stale 误标；note 14 条不进索引；单日上限播种死代码 |
| 宿主契约 | 7 | inject / 事件签名 / effect 主体正确；面板 9 路由绕宿主鉴权；export 默认写盘；幽灵工具名 |
| 性能资源 | 8 | 采集 32 ms/天、周收口 28.8 ms、检索 3 ms@101 条；扣分在外推：events 无保留、事实页全量重写 |
| 产品价值 | 5 | repeated 1.3%、跨天线索 1 条、实体页 71% 是自身源码、注入行与当前任务无关 |
| 工程可维护性 | 7 | 注释与自检突出；但 3 处「注释声称已修、实际没修」（播种 / stale 双写 / closedStamps） |

**一句话结论**：它是一个护栏很密、自检很勤的采集器，但**自检覆盖的恰好是它没坏的地方**——三条 P0/P1 都是「写完没人验」的静默失效。

## 2. 核实台账

状态：`坐实` = 代码+数据双证；`修正` = 主张部分成立；`推翻` = 不成立。

### P0

| 编号 | 主张 | 核实 | 证据 |
|---|---|---|---|
| P0-1 | 自动收口路径不写 `closedDays` ⇒ 跨午夜后每 5 分钟重收同一天 | **坐实** | `index.js:396-407` 只写 `lastClosedDay/lastClose/closedStamps`；`closedDays` 全包仅 `index.js:755`（手动工具）写入；判据 `lib/time.js:100`；`state.json` 无 `lastClose` ⇒ tick 从未收口过 |
| P0-2 | 手动收口不写 `closedStamps` ⇒ 该天之后事件永不重收 | **坐实** | `index.js:753-756` 缺 stamp；判据要求 `closedAt > 0`（`lib/time.js:105-110`）；`index/2026-W46.json` 最大 ts `2026-11-12T15:51:50`，而事件文件 mtime `23:59:28` ⇒ 15:51 之后 2,306 条（60.6%）未进产物 |

### P1

| 编号 | 主张 | 核实 | 证据 |
|---|---|---|---|
| P1-1 | 面板 9 条路由绕过宿主鉴权 | **坐实** | `lib/api.js:178-183,208`；实测宿主 `/api`→401 而 `/chronicle/api/facts`→200/16,698 B，POST 与伪造 Host 均受理 |

- **推翻**：S1 主张「重收会让事实 occurrences 翻倍」——不成立，`facts.js:208` 有明确防线（occurrences 由 timeline 推导）。

- **机械体检**：`plugin_doctor` 的 X1 / K3 / K4 三条非 PASS 全为误报——X1 基线停在 2026-10-07 的 `0.2.1-alpha.1`（真实宿主 `0.2.2-rc.1`，且 10 工具在线反证）；K3 的 `backfillTimer` 实际由 effect cleanup 释放（`index.js:590`），但**同一 WARN 的结论对、坐标错**（真正漏网的是 `index.js:923`）；K4 的 Schema 声明处无箭头函数。

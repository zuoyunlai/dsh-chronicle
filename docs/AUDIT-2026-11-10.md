## 1. 总评

**4.5 / 10 —— 工程纪律与产品直觉远超同类，但「记忆」这一层目前还没有真正成立。**

> **修订说明（第二轮）**：第三个审计代理从宿主 `app.asar` 解包出真实实现，
> 推翻了初版的两条结论——① peer 走廊 X1 FAIL 是误报（宿主实装 0.2.2-rc.1，满足 `^0.2.1-rc.1`）；
> ② 新增一条我自己引入的 P0（`focus: state.focus`，跨视图定位功能从上线起就是死的）。

两路独立审计在同一个点上撞见了：

> **这个插件记下的 16 条「记忆」，全部来自它自己的开发会话；当天真正干了活的另一个会话（WSL 迁移与磁盘优化），产出 0 条事实。**

而事实层**根本不进上下文**（唯一常驻的一行只讲编年层的计数），检索公式里权重最大的两项**恒为 0**（`entityHits` / `hopHit`），旗舰用例「上次那个坑」**实测 0 命中**。

所以严格说：**它现在是一个设计优秀、护栏扎实的数据采集与索引工具，还不是被证明有效的记忆系统。**

### 三个层面的问题

**A. 产品层（P0）**：定位「保存最有价值的」被自身的实现证伪——保存下来的是开发史，丢掉的是工作结论；且记忆不跨会话。

**B. 数据层（P0）**：默认配置下核心链路不通（rule 档事实库永远为空）；四个「静默失效」（上限不生效、23:50 窗口丢失、历史天跳过、围栏正则损坏）。

**C. 工程层（P0/P1）**：peer 走廊 FAIL（npm 装会被静默禁用）、脱敏对 JSON 键失效、事实层不幂等、孤儿页、假 `repeated` 徽标。

### 一个必须正视的负循环

> 记忆系统一旦让用户觉得「记了也没用」，用户会停止认真对话 → 语料质量下降 → 记忆质量再降。
>
> 当前的信号正指向它：**hits 14/16 = 87.5% 为 0**，唯二非零的两条是插件自己的当前状态。

这条负循环意味着**「普适性闸」（P0-10）不是优化，是止血**。

## 3. P0 — 阻塞级（12 项）

### 发布层（P0-1）

#### ~~P0-1 peer 走廊不相交 ⇒ npm 安装会被静默禁用~~ ❌ **撤回：误报**

**初版判断**：`package.json` peer 写 `^0.2.1-rc.1`，而 `plugin_doctor` X1 判「宿主 0.2.1-alpha.1 不满足」，
我据此列为发布阻塞并建议改成 `>=0.2.0-0 <0.3.0-0`。

**撤回理由**（从宿主 `app.asar` 解包实测）：

```
宿主实装 dsh-client-ui-sidebar-right = 0.2.2-rc.1
^0.2.1-rc.1 = >=0.2.1-rc.1 <0.3.0
0.2.2-rc.1 满足该区间 ✅
```

`plugin_doctor` 用的是**过期基线 0.2.1-alpha.1**，而宿主实际是 0.2.2-rc.1 ⇒ **X1 FAIL 是误报**。

**教训**：`plugin_doctor` 的宿主基线是写死的快照，**不能替代对真实宿主包的核实**。
本条已从 P0 降级为「工具误报，勿照着改」。

### 记忆系统层（P0-10 ~ P0-12）—— 这三条决定「它是不是记忆系统」

#### P0-10 事实层把工具自己的开发史当成了记忆，真实工作一条没进

**实测**：
```
16 条事实引用的会话数: 1  → ['session-16357994-e106-']
项目分布: {"dsh-chronicle": 16}
```

当天有 **2 个 session**：另一个是 `session-590c5325`（WSL 迁移与磁盘优化），
它产出了一条真正有价值的环境事实（vhdx 51.04G→28.95G、迁到 D 盘、数据无损），
却**一条事实都没进**——因为 `lib/facts.js:57` 的白名单只收
`decisions/pitfalls/rejected/conventions/questions`，**`projects` 与 `threads` 永远进不了事实层**。

**这直接证伪「把聊天中最有价值的地方保存起来」**：保存下来的恰恰是流水账（开发史），
丢掉的是有价值的结论（环境迁移事实）。

**修法**：
① prompt 加硬约束——「不要把关于本记录系统自身的实现细节记成事实，它们是工具的内部状态，不是用户的工作知识」；
② facts 加 `scope: general | tool-self`，`tool-self` 不进 MEMORY.md 主索引、不进规则导出；
③ `projects`/`threads` 里含具体路径/版本/数量/条件的条目可升级为事实
（例：「WSL 迁至 D 盘，vhdx 51.04G→28.95G，数据无损」）。

#### P0-11 检索公式里权重最大的两项在生产路径恒为 0

打分公式（`lib/recall.js:166`）：`3×entityHits + 1.5×hopHit + 1.0×importance + 0.8×recency + 0.4×lexical`

**实测**：
```
22 条里有 entities 的: 9    ← LLM 档给 decisions/pitfalls 硬编码 entities: []
22 条里有 files 的: 19     ← 但检索不读 files
查询「回捞」        → 3 条，首位 score 1.67
查询「上次那个坑」  → 0 条   ← 旗舰用例失败
查询「index.js」    → 0 条   ← 尽管 19/22 条带 files、图里有 27 个该节点
```

**两个不同的实体定义**：建图用 `entry.files`（`lib/entities.js:24-40`），
检索用 `entry.entities`（`lib/llm.js` 里对 decisions/pitfalls 等硬编码为空）⇒
`entityHits` 与 `hopHit` **永远是 0**，公式里最重的两项从未生效。

**得分分解**：`1.67 = 0.8(importance) + 0.8(recency) + 0.08(lexical)`
—— **92% 是常量底座，真实相关度只占 0.08–0.16**。
且 `recency`(0.8) 是 `lexical`(0.08) 的 **10 倍** ⇒ **旧的但精确的记录必然输给新的但无关的记录**，
这与「跨会话记忆」的目标正好相反。

**修法**：① 检索侧实体集合改成 `entities ∪ files basename`，与建图共用同一个函数；
② 加中文停用/高频词表做 IDF；③ `lexical` 提到 ≥1.5、`recency` 降到 ≤0.3；
④ `entityHits` 封顶 3 防子串刷分；⑤ 实体命中改分词后精确匹配（现在实体名「门」会命中任何含「门」的查询）；
⑥ 建**黄金查询集**（20 条自然语言问法，标注期望命中的 ref）做回归。

#### P0-12 事实层不进上下文 ⇒「跨会话记忆」事实上不跨会话

唯一常驻上下文的是一行 `injectText`（`index.js:715`），内容是**编年层的计数**
（`今天 2 个项目 · 4 条决策 · 6 个坑 · 最高分：…`）——**不含任何事实内容**。

检索路径（`index.js:866` 的 `searchEntries`）也只搜编年层条目，
facts 只能靠 `chronicle_facts` 列举（**无查询参数**）+ 单条读。

**后果**：新会话要想起「上次那个坑是什么」，模型必须主动调工具——
而没有任何指令鼓励它调。**「跨会话」这个核心承诺目前没有兑现。**

**修法**：① 注入行改成「一条约定 + 一个待避的坑」（从当天 facts 挑，
输出「今天有 X 项目的 N 条约定：…；遇到『…』先查 …」），仍是 1 行 ≤80 token，
但**注入的是记忆而不是流水账的元数据**；
② 加一条 systemPrompt 上下文：开工前若命中某项目，先 `chronicle_facts --project X` 拉一遍；
③ `chronicle_facts` 支持 `q` 查询参数。

### 数据层（P0-4 ~ P0-9、P0-13）

#### P0-13 「在关系图里定位」整个功能是死的（**本审计作者引入**）

`client.js:1046` 传的是 `focus: state.focus`，但 `focus` 是**另一个独立的 `useState`**（`client.js:829`），
`state` 的结构是 `{loading, error, entries, summary}`，**从来没有 `focus` 键**。

**后果链条（路径唯一，无歧义）**：
`state.focus` 恒为 `undefined` → `focusName` 恒为 `''`（`client.js:379`）→
自动居中分支永不执行（`394`）→ `focusKey` 恒为 `''`（`424`）→ 聚焦光环永不画（`522-533`）→
「聚焦：xxx / 清除」条永不出现（`434`）——**用户连清除都点不到**。

**也就是说 0.14.0 那个「点事实/线索行 → 跳图谱并定位」的功能，从上线起就是死的。**

**修法**：`client.js:1046` 改 `focus: focus`（一行）。并加最小回归断言。

#### P0-4 每日 400 条事件上限从未真正生效，且丢的是最新的数据

`lib/ingest.js:211` 的 `this.counts` **从不从磁盘播种**（只有去重键 `persisted` 在 `ingest.js:255` 播种）。
所以上限实际是「**每进程每次运行 400 条**」。

实测证据：
- 2026-11-09 落盘 **1169 行**，名义上限 400 ⇒ 至少 3 次进程生命周期（3×400=1200 ≥ 1169，数学吻合）
- `state.dropped = 651`（占当日推送量 1820 条的 36%）
- 丢弃发生在 `push`（`ingest.js:225`），key 已进 `seen`，**本进程内永不重试，无死信文件**
- **丢的是会话尾部**——事件按时间推入，被丢的是当天最新、最有价值的对话
- 采样偏差：超限丢弃发生在高频时段，往往正是工作密集的时段

**修法**：① `counts` 播种为「磁盘已有行数 + pending」；② 丢弃写入 `events-dropped/<day>.jsonl` 死信；
③ `chronicle_ping` 报出哪一天、丢了多少、丢的哪类 kind；④ 上限提到 5000 或改按重要度保留。

#### P0-5 默认档位 `scoring='rule'` 下事实库永远为空

链路（实测）：`index.js:126` 默认 `'rule'` → `lib/score.js` 的 `ruleScore` **不产出 `section` 字段**
（实测输出字段：`ref,ts,title,claim,importance,kind,ws,files,signals,basis`）→
`lib/facts.js:57` `factsOfDay` 只认 5 个 section → 返回 `[]` →
`lib/close.js` 的 `if (incoming.length > 0)` 守卫跳过 →
**`MEMORY.md` / `vault/facts/*.md` / `AGENTS.generated.md` / 面板事实页全部产不出来**。

且 `structureWarnings` 的「四块为空」告警要求 `labelled > 0` 才触发，只报「缺日结」——
**一份平铺、无结构、无事实的周文件看起来「完全成功」**。当前 vault 的 16 条事实全部来自手动 `--scoring llm`。

**修法**：规则档按 `kind` 映射 section（`decision→decisions`、`pitfall→pitfalls`、
`delivery/research/chore→threads`）；或 rule 档时显式返回 `facts:{facts:0, reason:'rule-mode-no-section'}` 并在工具输出里喊出来。

#### P0-6 23:50 收口与「事件写到 24:00」冲突 ⇒ 每天最后 10 分钟永远进不了事实库

实测：
```
closeDecision(23:52, lastClosedDay='2026-11-08') → {due:true, day:'2026-11-09'}
catchUpDays(次日 00:05, lastClosedDay='2026-11-09') → []      ← 补不回来
```

收口在 D 日 23:50 触发，事件持续写入到 24:00。**23:50–24:00 的决策/坑永远不会被提炼成事实**
（周文件次日会补上，因为 `daysOfWeek` 重算整周；但 `lib/close.js:326` 的事实提炼只取被收口那一天）。

**每天稳定丢 10 分钟高价值内容，且完全静默。**

**修法**：事实提炼与收口时刻解耦（收 D 时提炼到 24:00），或把收口推到 D+1 00:05，或加 `factsThrough` 游标。

#### P0-7 `catchUpDays` 把「已收口的最后一天」当成「更早的天都收过了」

`lib/time.js:95`：`if (lastClosedDay && day <= lastClosedDay) continue`。state 只存**一个** `lastClosedDay`，
没有「已收口日集合」。

实测：磁盘上 11-05..11-08 都有事件文件，但 `catchUpDays` 返回 `[]`——
**这些天永远不会被收口，也没有任何告警**。

可达场景：插件 X 日安装并收口 X 日；随后 backfill 回捞出更早日期的事件 → 生成更早的 `.jsonl` → 这些天此后永久跳过。

**修法**：state 存 `closedDays: []` 集合；`catchUpDays` 只跳过集合里真存在的日子；被跳过的日子在 `chronicle_ping` 列出。

#### P0-8 脱敏对「带引号的键」完全失效（安全）

`lib/redact.js:42` 的关键字与分隔符之间不允许闭引号，而带引号的键必然有。

实测：
```
LEAK  {"password": "hunter2secret"}      ← JSON 配置文件里的口令原样落盘
LEAK  {'api_key': 'abcd1234efgh'}
ok    password: hunter2secret
```
之后这些会被 `git add -A` 提交进 vault、被同步盘带走。**事后清理永远慢一步。**

**修法**：关键字与分隔符之间改 `["']?\s*[=:]`；补 `token`/`pwd`/`pass`/`authorization`/`x-api-key` 等键名。

#### P0-9 `extractJsonObject` 的围栏正则被写坏（**本审计作者引入**）

`lib/llm.js:213` 实际字节：
```js
const fenced = /```(?:json)?s*([sS]*?)```/i     ← \s 退化成了 s，[\s\S] 退化成 [sS]
```
同文件 `extractJsonArray`（`llm.js:156`）是正确的 `\s*([\s\S]*?)`。

**成因**：该函数是我用 `node -e "..."` 写的，bash 双引号把反斜杠吃掉了。**这是我自己造成的回归。**

**影响**：模型输出带 ```json 围栏且**围栏之前有中文或花括号**时 → 解析返回 null →
整个 digest（summary + sections + threads）全丢 → 退回数组分支 → 模型给的是对象 →
抛「输出不是 JSON」→ **整天退回规则分**。

这与生产数据吻合：`summaries:{"2026-11-09":""}`、周文件无 `> **日结**` 行、`structureWarnings` 报「缺日结」。

**这也推翻了 CHANGELOG 0.12.1 ③ 的成因判断**（当时写「filter() 丢元数据」并指望下次收口恢复）——
`mergeProjects` 那处修复是对的，真正的原因是本条正则损坏。

**修法**：恢复 `\s*([\s\S]*?)`；补单测覆盖「围栏前有花括号/中文」。

### 记忆系统层（P1-1 ~ P1-7）

### 客户端与宿主生命周期层（P1-18 ~ P1-20）

#### P1-18 路由重注册守卫是「粘性」的 ⇒ 面板永久 404，而自检说谎

`index.js:747`：`if (routeReport.ok) return () => {}`。`routeReport.ok` 全生命周期只置 true，
**路由被注销后没有任何地方把它置回 false**（`index.js:755-763` 的 disposer 只调路由 disposer）。

宿主 registry 语义：`ctx.inject` 的回调**在所需服务变化时会被卸载并重跑**。
所以 webServer 一旦被重新发布（TLS 重载后 listen 失败重试 / web-server 插件禁用启用 / 宿主热重载），
旧路由被注销 → inject 回调重跑 → **守卫直接挡掉** → 9 条路由全消失 → 面板永久 404。

**而 `chronicle_ping` 仍返回 `routes.ok=true`，渲染成「面板 API 已注册 9 条」——自检在撒谎。**

**修法**：在 `startRoutes` 返回的 disposer 里复位 `routeReport.ok = false`；或改用「活注册」判定而非布尔。

#### P1-19 ErrorBoundary 没有恢复路径 ⇒ 面板一次性报废

`client.js:1062-1083` 的 Boundary 只渲染错误信息，没有复位机制。
宿主 sidebar-right 的 `TabSlot` 用 `renderSlot` 渲染，重渲染产生同类型同位置元素 → React 复用 Boundary 实例 → `state.error` 保留。
配合 `keepMounted:true`（`client.js:1106`）跨会话 retainTab，**更不可能自愈**。

任一渲染期异常 → 面板在本次宿主生命周期内**永久废掉，只能重启 DSH**。

**修法**：给 Boundary 加可复位 key（官方推荐 `resetErrorBoundary` 手段）。

#### P1-20 客户端 1152 行 0 条测试

`tests/` 里没有任何一条针对 `client.js` 的测试。6 视图、力导向图、手势、错误边界、图表全无覆盖。
**P1-13（focus 失效）与 P1-19（Boundary 无恢复）两条都落在零覆盖区**——一条断言就能抓到 P1-13。

## 6. 值得肯定的设计（5 条）

1. **脱敏前置到写盘之前**，且在采集层就做（`ingest.js:193`、`backfill.js:110`）。密钥一旦写进 Markdown 就被 `git add -A` 提交、被同步盘带走，事后清理永远慢一步。**这是整条管线里最高价值的取舍**（尽管规则本身有 P0-9 的漏洞）。
2. **跨进程 `sid#seq` 去重扎实**：内存 Set + flush 时用磁盘已有键播种（`ingest.js:253-257`）。宿主重启会重放事件，只靠内存 Set 会写出重复行——生产数据重复键实测 **0**。
3. **校验优先于相信模型**：编造的 ref 整条丢弃、importance/kind 越界即丢、根因用原文反查。「宁可退回规则分也不接受编造证据」让 LLM 档可以安全开启。
4. **把「静默降级」变成显式告警**：`structureWarnings` + 工具输出打 warnings。0.11.0 那次 `mergeProjects` 丢元数据导致整份周文件退化成平铺条目——正是靠这道自检才被发现。
5. **时间边界的本地化是对的**：日/周边界一律用 `new Date(\`${day}T12:00:00\`)` 避开午夜与夏令时，ISO 周用「周四定位」避开跨年错位。实测跨零点、跨周边界、跨年周次全部正确。
